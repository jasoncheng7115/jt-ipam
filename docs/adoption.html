導入流程Adoption roadmap導入ガイド

給負責把 jt-ipam 帶進公司的網管與資訊主管：從安裝到自動化分成六個階段，依序開啟功能。每個階段都有明確的完成標準，做完再往下走，資料在每一步都可信。For the network admins and IT leads bringing jt-ipam into an organisation: six phases from install to automation, turning features on in order. Each phase has a clear finish line, and you move on only when it is met, so the data can be trusted at every step.jt-ipam を社内に導入するネットワーク管理者と情報システム部門の責任者向けのガイドです。インストールから自動化までを 6 つのフェーズに分け、順番に機能を有効にしていきます。各フェーズには完了の目安があり、それを満たしてから次へ進むので、どの段階でもデータを信頼できます。

規劃plan計画掃描scanスキャン落差gap差分

先有規劃，再讓機器補上事實Plan first, then let machines add the factsまず計画、事実は機械に補わせる

規劃是「應該如何」，掃描與整合是「實際如何」；先有規劃，落差才看得出來。The plan says how it should be; scans and integrations say how it is. Without the plan there is nothing to compare.計画は「あるべき姿」、スキャンと連携は「実際の姿」。計画がないと差が見えません。

來源sourceソース讀取read読み取りjt-ipam自動建立auto-create自動作成

先唯讀比對，再考慮自動建立Read-only first, auto-create laterまず読み取りで照合、自動作成は後で

整合一律唯讀；自動建立除了 LibreNMS 主 IP 之外都預設關閉。Integrations only read; auto-create is off by default except LibreNMS primary IPs.連携は読み取りのみ。自動作成は LibreNMS の主 IP 以外は既定でオフです。

每個階段都有完成標準Every phase has a finish line各フェーズに完了の目安

達到完成標準再往下；跳過的話，未授權 IP 這類偵測會一直誤報。Reach the finish line before moving on; skip it and checks such as unauthorised IPs keep raising false alarms.完了の目安を満たしてから次へ。飛ばすと未承認 IP などの検知が誤報を続けます。

jt-ipam 是集中記錄與管理的工具：它不會發放或回收位址，也不會封鎖設備。實際的發放與阻擋仍由你的 DHCP、防火牆與 NAC 負責。詳見定位說明。jt-ipam records and manages; it does not hand out or revoke addresses, and it does not block devices. Assignment and blocking stay with your DHCP, firewalls and NAC. See what it is.jt-ipam は記録と集中管理のための道具です。アドレスの払い出しや回収、機器の遮断は行いません。それらは引き続き DHCP・ファイアウォール・NAC の役割です。詳しくは位置づけをご覧ください。

常見地雷Common pitfallsよくある落とし穴
  • 還原需要同一把 ENCRYPTION_KEY（在 /etc/jt-ipam/backend.env）才解得開整合帳密等加密欄位。備份檔已包含這個檔案，所以異地備份要當機密保管。A restore needs the same ENCRYPTION_KEY (in /etc/jt-ipam/backend.env) to decrypt integration credentials and other encrypted fields. The backup includes that file, so treat off-site copies as secrets.復元には同じ ENCRYPTION_KEY（/etc/jt-ipam/backend.env 内）が必要で、これがないと連携の認証情報などの暗号化項目を復号できません。バックアップにはこのファイルが含まれるので、外部保管のコピーは機密として扱ってください。
  • 在 jt-ipam 前面再放一層自己的反向代理或負載平衡器時，那一層也要設同一套安全標頭；安全標頭不會自動跨過多出來的那一跳。If you put your own reverse proxy or load balancer in front, it must send the same security headers; they do not survive the extra hop on their own.jt-ipam の前段に独自のリバースプロキシやロードバランサーを置く場合、そこでも同じセキュリティヘッダーを設定してください。ヘッダーは余分な中継を自動では通り抜けません。
  • 主機規格照建議值準備（4 核心、8 GB、50 GB）：稽核記錄、IP 歷程與備份會一直成長。自架 LLM 不要和 jt-ipam 放同一台。Size the host at the recommended 4 vCPU, 8 GB and 50 GB: the audit log, IP history and backups keep growing. Do not run a self-hosted LLM on the same machine.ホストは推奨値（4 コア、8 GB、50 GB）で用意してください。監査ログ、IP の履歴、バックアップは増え続けます。自前の LLM を同じマシンで動かすのは避けてください。

常見地雷Common pitfallsよくある落とし穴
  • 代理的位置決定看得到什麼：ARP 與 MAC 只在同一個廣播網域拿得到，要知道 MAC 與廠牌，代理就要放在那個網段裡（或在那個 VLAN 有介面的主機上）；跨過路由就只剩 ICMP。Where an agent sits decides what it sees: ARP and MACs are only available inside the same broadcast domain, so to learn MACs and vendors the agent must live in that network (or on a host with an interface in that VLAN). Across a router, only ICMP is left.エージェントの設置場所で見えるものが決まります。ARP と MAC は同じブロードキャストドメイン内でしか取得できないため、MAC とメーカーを知りたいならエージェントをそのネットワーク内（またはその VLAN にインターフェースを持つホスト）に置きます。ルーターを越えると ICMP しか使えません。
  • 代理與目標之間有防火牆擋 ICMP 時，整段會看起來都離線；先確認代理到目標網段的 ICMP 是通的。A firewall that drops ICMP between agent and target makes a whole network look offline; check that ICMP from the agent reaches it first.エージェントと対象の間に ICMP を遮断するファイアウォールがあると、ネットワーク全体がオフラインに見えます。まずエージェントから対象ネットワークへ ICMP が通ることを確認してください。
  • 大子網路不要為了掃描切小，照實際遮罩登記（例如 /8）。子網路的「掃描範圍」維持「自動」：超過 4,096 個位址時，已登記的 IP 與最近 7 天 ARP 看過的位址每一輪都掃，其餘位址在背景探索；改成「整個子網路」的話，大子網路一輪只掃得到一段，設備會在兩次掃描之間被判成離線。Do not split a large subnet just for scanning; register its real mask (a /8, for example) and keep the subnet's "Scan scope" at Automatic: above 4,096 addresses, registered IPs and addresses seen in ARP in the last 7 days are scanned every cycle and the rest are explored in the background. With "Whole subnet", a large subnet is covered one chunk per cycle and devices show offline between scans.スキャンのために大きなサブネットを分割せず、実際のマスク（例：/8）で登録してください。サブネットの「スキャン範囲」は「自動」のままにします。4,096 アドレスを超えると、登録済みの IP と過去 7 日間に ARP で見えたアドレスを毎周スキャンし、残りはバックグラウンドで探索します。「サブネット全体」にすると、大きなサブネットは 1 周に一区画しかスキャンできず、スキャンの間に機器がオフラインと判定されます。
  • 「自動收錄未登錄的 IP」預設關閉，建議維持關閉：位址一旦收錄，私接的設備就不會再出現在未授權 IP 清單。"Record unregistered IPs automatically" is off by default; keep it off.   • OS 偵測屬於侵入性探測，可能觸發 IDS 告警；開啟前先知會資安團隊，間隔拉長。DHCP 伺服器偵測會在網段上廣播，逐個子網路決定要不要開。OS detection is an intrusive probe that may trip IDS alerts; tell your security team first and keep the interval long. DHCP server discovery broadcasts on the network, so decide per subnet.OS 検出は侵入的な探査で、IDS の警告を引き起こすことがあります。有効にする前にセキュリティ担当へ知らせ、間隔を長めにしてください。DHCP サーバーの検出はネットワーク上でブロードキャストするので、サブネットごとに判断してください。

常見地雷Common pitfallsよくある落とし穴
  • 改用外部 OpenAI 相容服務時，子網路、主機名稱與拓樸會送到該服務；資料不能離開公司就維持自架。Switching to an external OpenAI-compatible service sends subnets, hostnames and topology to that provider; keep it self-hosted if the data must not leave.外部の OpenAI 互換サービスに切り替えると、サブネット、ホスト名、トポロジーがその事業者に送られます。データを社外に出せない場合は自前のままにしてください。
  • 嵌入模型的維度要和資料庫欄位一致（預設 768），否則語意搜尋不會報錯，只是永遠找不到東西；換模型後在設定頁按「檢查維度」。The embedding model's dimension must match the database column (768 by default); otherwise semantic search raises no error and simply never finds anything. After changing models, press "Check dimension" on the settings page.埋め込みモデルの次元はデータベースの列と一致させてください（既定 768）。一致しないと意味検索はエラーを出さず、ただ何も見つからなくなります。モデルを変えたら設定ページで「次元を確認」を押してください。
  • 升級或重啟服務會切斷進行中的主控台連線與檔案上傳，請挑維護時段進行。Upgrades and service restarts cut console sessions and file uploads in progress; schedule them in a maintenance window.アップグレードやサービスの再起動は、進行中のコンソール接続とファイルのアップロードを切断します。メンテナンスの時間帯に行ってください。
  • 憑證代理的金鑰等同它範圍內所有憑證的私鑰，要當最高機密保管。A certificate agent's key is as good as the private keys of every certificate in its scope; guard it as a top-tier secret.証明書エージェントのキーは、その範囲内のすべての証明書の秘密鍵に相当します。最高機密として保管してください。
