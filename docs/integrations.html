OPNsense

唯讀Read only読み取りのみREST API

透過 OPNsense REST API 讀取 ARP、DHCP、防火牆規則、別名、NAT 與 VPN，讓 IPAM 知道每個位址在防火牆上被誰看到、被哪些規則管到。Reads ARP, DHCP, firewall rules, aliases, NAT and VPN over the OPNsense REST API, so IPAM knows which addresses the firewall sees and which rules cover them.OPNsense REST API で ARP、DHCP、ファイアウォールルール、エイリアス、NAT、VPN を読み取り、各アドレスがファイアウォールでどう見えているか、どのルールが関わるかを IPAM で把握できます。

取得的資料What it reads取得するデータ

  • ARP 表與防火牆自己的介面位址ARP table and the firewall's own interface addressesARP テーブルとファイアウォール自身のインタフェースアドレス
  • DHCP 租約、發放範圍與固定分配（Kea、dnsmasq、ISC）DHCP leases, ranges and reservations (Kea, dnsmasq, ISC)DHCP リース、配布範囲、固定割り当て（Kea、dnsmasq、ISC）
  • 篩選規則、別名，以及 NAT（Port Forward / 1:1 / Outbound）Filter rules, aliases and NAT (Port Forward / 1:1 / Outbound)フィルタールール、エイリアス、NAT（Port Forward / 1:1 / Outbound）
  • OpenVPN 連線，以及 WireGuard / IPsec 站對站通道OpenVPN sessions and WireGuard / IPsec site-to-site tunnelsOpenVPN 接続、WireGuard / IPsec のサイト間トンネル

管理效益Management benefit管理上の効果

  • 位址的最後出現時間與 MAC 跟著防火牆更新，不必等掃描；租約主機名稱成為名稱來源之一Last seen and MAC follow the firewall without waiting for a scan; lease host names become a name source最終確認時刻と MAC がスキャンを待たずに更新され、リースのホスト名も名前の情報源になります
  • IP 詳細資料列出涵蓋這個位址的規則、別名與 NAT；IP 變更評估也會查到IP details list the rules, aliases and NAT covering the address; IP change assessment checks them tooIP 詳細にそのアドレスに関わるルール、エイリアス、NAT が表示され、IP 変更評価でも確認されます
  • 規則異動偵測：規則一變就通知並附差異；懸空轉發、別名成員未登記列入異常偵測Rule-change detection notifies with a diff; dangling forwards and unregistered alias members show in anomaly detectionルール変更検知が差分付きで通知し、宙に浮いた転送や未登録のエイリアスメンバーは異常検知に出ます
  • VPN 通道畫在 IP 拓樸圖；防火牆被認定為已知 DHCP 伺服器，不會被報成非法 DHCPVPN tunnels appear on the IP topology map; the firewall counts as a known DHCP server, not a rogue oneVPN トンネルが IP トポロジーに描かれ、ファイアウォールは既知の DHCP サーバーとして扱われ不正 DHCP と誤報されません

需要準備What to prepare準備するもの

  • 建議 OPNsense 24.1 以上；jt-ipam 伺服器要連得到它的 HTTPS 管理介面OPNsense 24.1 or later recommended; the jt-ipam server must reach its HTTPS management interfaceOPNsense 24.1 以降を推奨。jt-ipam サーバーから HTTPS 管理画面に到達できること
  • 唯讀權限的 API key / secretAn API key / secret with read-only privileges読み取り権限のみの API key / secret
  • 要讀舊式 Port Forward 與 ISC 固定分配時，帳號還要能下載設定備份（config.xml，內含敏感設定）For legacy Port Forward and ISC static mappings the account must also download the config backup (config.xml, which holds sensitive settings)旧式 Port Forward と ISC の固定割り当てを読むには、設定バックアップ（機密情報を含む config.xml）のダウンロード権限も必要
  • 多台防火牆共用相同私有網段時，設定子網路關聯範圍與「介面 → 子網路對應」When several firewalls share the same private ranges, set the subnet scope and the "Interface → subnet map"複数のファイアウォールが同じプライベート網を使う場合は、サブネットの範囲と「インタフェース → サブネットの対応」を設定

限制與注意Limits and notes制限と注意

  • 只讀得到 Firewall > Automation > Filter 建立的規則；傳統 Firewall > Rules 沒有 API（26.1 起有移轉工具）Only rules made under Firewall > Automation > Filter are readable; legacy Firewall > Rules has no API (26.1 adds a migration tool)読めるのは Firewall > Automation > Filter で作ったルールのみ。従来の Firewall > Rules には API がありません（26.1 から移行ツールあり）
  • WireGuard 要有 WireGuard API（舊版需 os-wireguard 外掛）；IPsec 需新版 swanctl API（約 24.x 起）WireGuard needs the WireGuard API (the os-wireguard plugin on older releases); IPsec needs the newer swanctl API (about 24.x onwards)WireGuard には WireGuard API（旧版では os-wireguard プラグイン）、IPsec には新しい swanctl API（おおむね 24.x 以降）が必要
  • 租約裡 IPAM 沒有的位址預設略過；「自動建立 IPAM 沒有的位址」選用、預設關閉Lease addresses IPAM lacks are skipped by default; "Create addresses IPAM does not have" is optional and off by defaultIPAM に無いリースのアドレスは既定でスキップ。「IPAM に無いアドレスを作成する」は任意で既定オフ
  • 寫回功能另外設定：防火牆別名推送、憑證推送；別名也可提供給 GraylogWrite-back is set up separately: alias push, certificate push; aliases can also feed Graylog書き戻しは別途設定：エイリアス反映、証明書の配信。エイリアスは Graylog にも提供できます

pfSense

唯讀Read only読み取りのみREST API

透過 pfSense-pkg-RESTAPI 套件讀取 ARP、DHCP、別名、規則與 NAT，pfSense 上的位址、租約與規則都能在 IPAM 對照。Reads ARP, DHCP, aliases, rules and NAT through the pfSense-pkg-RESTAPI package, so addresses, leases and rules on pfSense line up with IPAM.pfSense-pkg-RESTAPI パッケージ経由で ARP、DHCP、エイリアス、ルール、NAT を読み取り、pfSense 上のアドレス、リース、ルールを IPAM と突き合わせられます。

取得的資料What it reads取得するデータ

  • ARP 表與防火牆自己的介面位址ARP table and the firewall's own interface addressesARP テーブルとファイアウォール自身のインタフェースアドレス
  • DHCP 租約、發放範圍（含額外集區）與固定分配DHCP leases, ranges (including extra pools) and static mappingsDHCP リース、配布範囲（追加プールを含む）、固定割り当て
  • 別名、防火牆規則、NAT（Port Forward / Outbound）Aliases, firewall rules, NAT (Port Forward / Outbound)エイリアス、ファイアウォールルール、NAT（Port Forward / Outbound）

管理效益Management benefit管理上の効果

  • 位址的最後出現時間、MAC 與租約主機名稱跟著防火牆自動更新Last seen, MAC and lease host names update from the firewall automatically最終確認時刻、MAC、リースのホスト名がファイアウォールから自動更新されます
  • IP 詳細資料與 IP 變更評估列出涵蓋這個位址的規則與別名IP details and IP change assessment list the rules and aliases covering the addressIP 詳細と IP 変更評価に、そのアドレスに関わるルールとエイリアスが表示されます
  • 規則異動偵測，加上規則劣化檢查：any 對 any 放行、WAN 對任意來源開管理埠、懸空轉發、別名成員未登記Rule-change detection plus rule-rot checks: any-to-any pass, management ports open to anyone on WAN, dangling forwards, unregistered alias membersルール変更検知に加え、any から any の許可、WAN で管理ポートを全開放、宙に浮いた転送、未登録のエイリアスメンバーを検出
  • 埠轉發與 WAN 上指向單一內部位址的放行規則，列入「對外開放服務」Port forwards and WAN pass rules to a single internal address appear in "Exposed services"ポート転送と、WAN で単一の内部アドレス宛ての許可ルールが「公開されているサービス」に載ります

需要準備What to prepare準備するもの

  • 在 pfSense 安裝 pfSense-pkg-RESTAPI（pfrest.org），把 API Key 加進認證方式並建立一把 keyInstall pfSense-pkg-RESTAPI (pfrest.org), add API Key to the auth methods and create a keypfSense-pkg-RESTAPI（pfrest.org）を導入し、認証方式に API Key を加えてキーを作成
  • 建議用專用、權限最小的帳號建立 keyCreate the key under a dedicated account with the least privilegesキーは専用で最小権限のアカウントで作成することを推奨
  • jt-ipam 伺服器要連得到管理介面 HTTPS；自簽憑證要關閉「驗證 TLS」（頁面會持續警示）The jt-ipam server must reach the HTTPS management interface; turn off TLS verification for self-signed certificates (the page keeps warning)jt-ipam サーバーから HTTPS 管理画面に到達できること。自己署名証明書なら TLS 検証をオフ（画面に警告が出続けます）

限制與注意Limits and notes制限と注意

  • pfSense CE 2.8.x 沒有內建 REST API，一定要裝這個第三方套件pfSense CE 2.8.x has no built-in REST API; the third-party package is requiredpfSense CE 2.8.x には標準の REST API がなく、このサードパーティパッケージが必須
  • 不讀 VPN 連線；NAT 跟著「規則」一起同步VPN sessions are not read; NAT is synced together with rulesVPN 接続は読みません。NAT はルールと一緒に同期されます
  • 租約裡 IPAM 沒有的位址預設略過；自動建立選用、預設關閉Lease addresses IPAM lacks are skipped by default; auto-create is optional and off by defaultIPAM に無いリースのアドレスは既定でスキップ。自動作成は任意で既定オフ
  • 寫回另外設定：憑證推送；別名可提供給 GraylogWrite-back is separate: certificate push; aliases can feed Graylog書き戻しは別途：証明書の配信。エイリアスは Graylog にも提供できます

FortiGate

唯讀Read only読み取りのみREST API

透過 FortiOS REST API 唯讀同步（只發 GET，不更動任何設定），支援多 VDOM。Read-only sync over the FortiOS REST API (GET only, nothing on the firewall changes), with multi-VDOM support.FortiOS REST API による読み取り専用の同期（GET のみで設定は一切変更しません）。複数 VDOM に対応。

取得的資料What it reads取得するデータ

  • ARP 表與防火牆自己的介面位址ARP table and the firewall's own interface addressesARP テーブルとファイアウォール自身のインタフェースアドレス
  • DHCP 租約、發放範圍與固定分配DHCP leases, ranges and reservationsDHCP リース、配布範囲、固定割り当て
  • 防火牆政策、位址物件與位址群組Firewall policies, address objects and address groupsファイアウォールポリシー、アドレスオブジェクト、アドレスグループ
  • NAT：VIP（埠轉發）與 IP poolNAT: VIPs (port forwards) and IP poolsNAT：VIP（ポート転送）と IP プール
  • IPsec 站對站通道，以及 SSL-VPN 使用者分到的位址IPsec site-to-site tunnels and the addresses given to SSL-VPN usersIPsec サイト間トンネルと、SSL-VPN ユーザーに割り当てられたアドレス

管理效益Management benefit管理上の効果

  • 位址的上線時間、MAC 與租約主機名稱跟著防火牆更新Liveness, MAC and lease host names follow the firewall稼働確認、MAC、リースのホスト名がファイアウォールに追従します
  • IP 詳細資料找得到透過位址物件引用這個 IP 的政策；IP 變更評估一併檢查IP details find the policies that reference the IP through address objects; IP change assessment checks them tooアドレスオブジェクト経由でその IP を参照するポリシーが IP 詳細に出て、IP 変更評価でも確認されます
  • 政策異動偵測；VIP 埠轉發列入「對外開放服務」與懸空轉發檢查Policy-change detection; VIP port forwards feed "Exposed services" and the dangling-forward checkポリシー変更検知。VIP のポート転送は「公開されているサービス」と宙に浮いた転送の検出に使われます

  • 唯讀的 REST API 管理員與 API token（以 Authorization 標頭傳送）A read-only REST API administrator and its API token (sent in the Authorization header)読み取り専用の REST API 管理者と API トークン（Authorization ヘッダーで送信）
  • jt-ipam 伺服器要連得到管理介面；REST API 管理員的信任主機要包含 jt-ipamThe jt-ipam server must reach the management interface; include it in the API administrator's trusted hostsjt-ipam サーバーから管理画面に到達でき、API 管理者の信頼済みホストに含まれること

It reads the registered devices and their online state, receives client reports, and pushes them to jt-ipam. Once a device is mapped to an IP record, you can connect with RustDesk straight from the IP page.hbbs が動く RustDesk ホストに専用の「RustDesk エージェント」（スキャンエージェントとは別物）を導入します。登録済みデバイスとオンライン状態を読み取り、クライアントからの報告を受け取って jt-ipam に送ります。デバイスが IP レコードに対応付けられると、IP ページから直接 RustDesk で接続できます。

接上自架或外部的 LLM 伺服器後，提供 AI 對話、語意搜尋、AI 巡檢與 AI 判讀。事實一律由 jt-ipam 的確定性查詢取得，模型只負責理解問題與敘述結果。Connect a self-hosted or external LLM server to get AI chat, semantic search, AI review and AI interpretation. Facts always come from deterministic jt-ipam queries; the model only understands the question and writes up the result.自前または外部の LLM サーバーを接続すると、AI 対話、意味検索、AI 点検、AI 判読が使えます。事実は常に jt-ipam の決定的なクエリから取得し、モデルは質問の理解と結果の説明だけを担います。

MCP server

Streamable HTTP stdio

jt-ipam 內建 MCP（Model Context Protocol）伺服器，讓外部的 LLM 用戶端與自動化腳本用同一組工具查詢 IPAM，每個工具都經過同一道權限閘。jt-ipam has a built-in MCP (Model Context Protocol) server, so external LLM clients and automation can query the IPAM through the same tools, each behind the same permission gate.jt-ipam は MCP（Model Context Protocol）サーバーを内蔵し、外部の LLM クライアントや自動化スクリプトが同じツール群で IPAM を照会できます。各ツールは同じ権限チェックを通ります。

  • 計算與查詢工具（CIDR、DNS、GeoIP、OUI、畫面位置），任何帳號都可用Calculation and lookup tools (CIDR, DNS, GeoIP, OUI, where things are in the UI), open to any account計算・照会ツール（CIDR、DNS、GeoIP、OUI、画面上の場所）はどのアカウントでも利用可
  • 逐物件資料（IP、子網路、裝置），依呼叫者的可見範圍過濾Per-object data (IPs, subnets, devices), filtered by what the caller can seeオブジェクト単位のデータ（IP、サブネット、デバイス）は呼び出し元の可視範囲で絞り込み
  • 全域基礎設施（VLAN、NAT、防火牆、DNS、拓樸）要管理員或萬用讀取授權Global infrastructure (VLANs, NAT, firewalls, DNS, topology) needs admin or global read全体インフラ（VLAN、NAT、ファイアウォール、DNS、トポロジー）は管理者または全体読み取り権限が必要
  • 管理資料（AI 巡檢、異常、代理、憑證等）只給管理員；會異動資料的工具要管理員且憑證不是唯讀Admin data (AI review, anomalies, agents, certificates and more) is admin only; tools that change data need admin and a non-read-only credential管理データ（AI 点検、異常、エージェント、証明書など）は管理者のみ。変更系ツールは管理者かつ読み取り専用でない資格情報が必要

  • 設備憑證選擇器：OPNsense 存檔前就能讀出設備上的憑證來選要替換哪一張；pfSense 可看哪張在用、何時到期Device certificate picker: on OPNsense, read the device's certificates before saving and pick the one to replace; on pfSense, see which is in use and when it expires機器証明書の選択：OPNsense では保存前に機器上の証明書を読み出して置き換える 1 枚を選択。pfSense では使用中の証明書と期限を確認

需要準備What to prepare準備するもの

  • 另建一組只給換憑證用的帳號或金鑰（既有的整合帳號多半是唯讀）A separate account or key used only for certificate changes (existing integration accounts are usually read only)証明書の切り替え専用のアカウントまたはキーを別途作成（既存の連携用は多くが読み取り専用）
  • 權限：FortiGate 要 system 與 VPN 寫入；OPNsense 要憑證管理與重啟服務；Palo Alto 要匯入憑證、改設定、commit；pfSense 要裝 REST API 套件 v2Rights: FortiGate needs system and VPN write; OPNsense needs certificate management and service restart; Palo Alto needs certificate import, config change and commit; pfSense needs the REST API package v2権限：FortiGate は system と VPN の書き込み、OPNsense は証明書管理とサービス再起動、Palo Alto は証明書インポート・設定変更・commit、pfSense は REST API パッケージ v2 が必要
  • jt-ipam 伺服器要能以 https:// 連到設備的管理 APIThe jt-ipam server must reach the device's management API over https://jt-ipam サーバーから機器の管理 API へ https:// で接続できること
  • 要確認的服務不在 API 位址上時（例如 SSL VPN），填「確認位址（主機:埠）」If the service to check is not on the API address (SSL VPN, for example), fill in the verify address (host:port)確認するサービスが API のアドレスと異なる場合（SSL VPN など）は確認先（ホスト:ポート）を入力

限制與注意Limits and notes制限と注意

  • Beta：OPNsense 網頁管理介面的憑證已在真機驗證，其他廠牌尚未在真機上驗證Beta: the OPNsense web GUI certificate has been verified on a real device; other vendors have not been verified on real hardware yetBeta：OPNsense の Web GUI 証明書は実機で検証済み、その他のメーカーはまだ実機で検証していません
  • 推之前就連不到確認位址時只標「未確認」、不會換回；只匯入不換上也算未確認If the verify address was unreachable before the push, the result is "unverified" and nothing is rolled back; import-only also counts as unverified配布前から確認先に接続できない場合は「未確認」となり元に戻しません。インポートのみも未確認扱い
  • 不支援 Check Point；設備上舊的憑證不會自動刪除Check Point is not supported; old certificates on the device are not deleted automaticallyCheck Point は非対応。機器上の古い証明書は自動削除しません
  • OPNsense 重啟網頁管理介面時，管理連線可能短暫中斷Restarting the OPNsense web GUI can briefly cut management sessionsOPNsense の Web 管理画面を再起動すると管理接続が一時的に切れることがあります
